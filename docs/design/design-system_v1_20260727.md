# Nutrition App デザインシステム v1 — トークンと共通規約

2026-07 のビジュアル仕上げ（#85–#94）で確立した**デザイントークンと適用規約**の正本。
色・意味づけの原則は `ui_design_v0_1` を土台とし、本書はその上に載る
**マージン設計 / 深度設計 / モーション / ボタン共通資産化**をまとめる。
すべての実体は `src/styles/tokens.css`（トークン）と `src/styles/globals.css`
（ユーティリティ）にあり、各コンポーネントはハードコードせずトークンを参照する。

> 変更禁止の大原則（v0.1 継承）: 警告色（赤）を増やさない／ゴールド＝達成バッジ限定／
> 断定せず事実提示／公式 seed 値の手編集禁止。

---

## 1. マージン / スペーシング設計

**8px リズム**を単一の基準とする。縦の余白がこのスケールに乗ることで画面間の一貫性が生まれる。

| トークン | 値 | 主な用途 |
| --- | --- | --- |
| `--space-1` | 4px | アイコンと文字、微調整 |
| `--space-2` | 8px | チップ内 gap、隣接要素 |
| `--space-3` | 12px | 見出し下、コンパクトな行間 |
| `--space-4` | 16px | カード padding、標準ブロック間 |
| `--space-5` | 24px | セクション間の標準リズム |
| `--space-6` | 32px | 画面上部・大区切り |

### 規約
- **セクション間は `--space-5`（24px）で統一**。記録タブの各セクション
  （いつもの/料理/候補/下書き/サプリ）は `marginTop: var(--space-5)` を持つ。
- **見出しは上に息を、下に均等な間隔**。例: 記録タブの `間食を記録` は
  `margin: var(--space-5) 0 var(--space-4)`（上24・下16）。上を詰めない。
- **タップ要素の直後は最低 `--space-4`（16px）空ける**（区分ボタン→検索ボックス等）。
- 8px 非整数（6/9/10/14/18px 等）は**最寄りのトークンにスナップ**して新規追加しない。
  既存のハードコード値を触るときは同時にトークン化する。
- 横 padding は要素の性格に従う（チップは `4px 10px` 系）が、**縦マージンは必ずスケール準拠**。

## 2. 深度 / エレベーション設計

影を1種で使い回さず、**z-order の意味に応じた3段**で表現する（#85/#89）。
「フラットなミント面」と「浮く白カード」が別ルールで散らばらないよう、面の深度言語を統一する。

| トークン | 役割 | 例 |
| --- | --- | --- |
| `--elev-rest` | 面・区切り（最小の持ち上がり） | ミントのヘッドライン、コールアウト |
| `--elev-raised` | カード（#59 のカード影を一元化） | ホームの各カード、UL カード |
| `--elev-overlay` | シート/モーダル（最前面） | 将来のボトムシート等 |
| `--border-hairline` | `1px` の淡い境界 | 面のふち。影と併用 |

### 規約
- **ミント面にも白カードにも同じ深度規則を適用**。ミントのコールアウトは
  `--border-hairline` ＋ `--elev-rest` を持ち、白カードは `--elev-raised`。
  「ミントはフラット・白だけ影」という不揃いを作らない（#89）。
- 立体化（花の中心など装飾的な奥行き）は**可読性に奉仕する範囲まで**。
  内影 opacity ≤ 0.28・ハイライト1本・近似色グラデのみ。これを超える光沢は
  スキュアモーフ退化として不可（#87 ガードレール）。

## 3. 角丸 / タイプ / モーション

### 角丸（radius）
`--radius-sm`(8) チップ・小コントロール／`--radius-md`(12) タイル・内側パネル／
`--radius-lg`(16) カード・シート／`--radius-pill`(999) 丸トグル。混在していた 8/10/12/14/16 は
この4段に集約。

### タイプスケール
`--fs-caption`(11)〜`--fs-num-hero`(34)、行高 `--lh-tight/snug/body`、
太さ `--fw-reg/med/bold`。主要数値はセリフ（`--font-numeric`）、本文は `--font-ui`。

### モーション
`--dur-fast`(.08s) 押下／`--dur-base`(.18s) 展開／`--dur-slow`(.32s) 開花。
イージング `--ease-standard` / `--ease-emph`。
**すべてのモーションは `prefers-reduced-motion: reduce` を尊重**する
（花の開花 #61・バー伸長 #66・押下 #90 は本トークンに統一）。

## 4. ボタン共通資産化

### 現状（課題）
ボタンは各画面のインライン `styles` に個別定義され重複している
（`mealTypeButton` / `zoneButton` / `dateNavButton` / `saveButton` / 週ナビ等）。
色・角丸・最小タップ高さ（`--tap-target-min`=44px）は概ね揃っているが、
**単一の出所が無く**、微妙な差異と将来の一括変更コストが残る。

### 押下フィードバック（実装済み・共通）
`globals.css` の `.pressable` ユーティリティを唯一の押下表現とする。
`:active` で `scale(0.98)`、`--dur-fast` / `--ease-standard`、reduced-motion 尊重。
タップ可能なタイル/チップ/CTA/トグルに `className="pressable"` を付与する。
**新しい押下演出をコンポーネント側で自作しない。**

### 提案（次段の資産化）
共有 `Button` コンポーネントに集約し、バリアントで意味を表す。

```
<Button variant="primary" | "ghost" | "segment" | "icon"
        selected? size? disabled? />
```

- `variant=primary`: 塗り（`--color-primary` / 文字 `--color-base`）＝主アクション（保存・記録）
- `variant=ghost`: 枠線（`--color-primary`）＝副アクション（いつもの・区分）
- `variant=segment`: 選択トグル（active=塗り / idle=淡枠）＝ゾーン/食事区分
- `variant=icon`: 44px 正方（日付ナビ ←→）
- 共通: `--radius-sm`、`min-height: var(--tap-target-min)`、`.pressable` を内蔵、
  `font: inherit`、フォーカスリング（`:focus-visible`）を1箇所で定義
- 意味づけ規約: 塗りゴールドはボタンに使わない（ゴールド＝達成バッジ限定）。
  警告色（赤）は使わない。破壊的操作（削除）は ghost＋確認で表現し赤に頼らない。

> 資産化は独立タスク（挙動不変のリファクタ）。着手時は各画面の既存差異を
> `Button` のバリアントに写像し、見た目を変えずに出所を一本化する。

## 5. 適用チェックリスト（新規画面・レビュー時）

- [ ] 縦マージンは `--space-*` に乗っているか（8px 非整数を新規追加していないか）
- [ ] セクション間は `--space-5`、カード padding は `--space-4` か
- [ ] 面の深度は `--elev-*` の3段のいずれかか（影の自作をしていないか）
- [ ] 角丸は `--radius-*` の4段か
- [ ] タップ要素に `.pressable` が付いているか／`--tap-target-min` を満たすか
- [ ] モーションは `--dur-*`/`--ease-*` かつ reduced-motion 尊重か
- [ ] 色は意味どおりか（赤なし・ゴールドは達成のみ・差し色は装飾/演出限定）
