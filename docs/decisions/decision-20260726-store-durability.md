# ローカルJSONストアの永続性堅牢化（消失防止）

- 日付: 2026-07-26
- ステータス: 採用
- 関連: [[decision-20260715-mvp-data-api-simplification]]（MVPはローカルJSON永続化）
- きっかけ: ユーザー報告「サプリの製品プリセット・料理の登録が消えた」

## 背景

meals / supplements / supplement-products / recipes / profile はローカルJSONで
永続化している。全ストアが同じ危険パターンだった:

- **`readAll` が全ての読取り例外で `[]` を返す** — ファイルが破損/途中書き（例: dev
  サーバー再起動やクラッシュで書き込みが中断されると 0 バイトや途中まで）になると、
  次の変更は `read(=[]) → write([...[], new])` となり **既存データを空で上書きして消す**。
- **書き込みが非アトミック** — `writeFile` で直接上書き。中断でファイルが壊れやすく、
  上の消失を誘発する。

## 決定

共通ヘルパー `src/server/store/jsonArrayStore.ts` を新設し、全ストアを移行:

1. **読取りは破損時に `[]` を返さず throw する**（`readJsonArray`）。
   - 欠損(ENOENT)・空ファイルは正当な空リスト → `[]`。
   - 存在するが JSON パース不可 / 配列でない → **throw**。
   - 変更系は read→modify→write なので、破損読取りが throw すれば write に到達せず
     **既存ファイルは保全される**（上書き消失が構造的に起きない）。
2. **書き込みはアトミック**（`writeJsonArray` / `writeJsonObject`）。
   - 一時ファイルに書いてから `rename`（同一FSでアトミック）。中断で本ファイルが
     途中状態になることがない。
- profile も同様にアトミック書込みへ。

## 影響
- テスト 216 → 224（jsonArrayStore: 欠損/空/正常/破損throw/非配列throw/アトミック/
  一時ファイル残さない/破損時に変更が上書きしない）。
- API・契約・データ形式は不変（26オペ）。既存の有効データはそのまま読める。
- トレードオフ: 破損ファイルは GET 系で 500 になり得る（従来は空表示で隠蔽）。
  アトミック書込みで破損自体が起きにくくなるため許容。破損を隠して消すより surfacing。

## 運用の再発防止（プロセス）
- **検証はユーザーの稼働 dev サーバー（実データ）に対して行わない**。`NUTRITION_DATA_DIR`
  を独立ディレクトリに向けるか、ユニットテストで代替する。
- 復旧: アプリの「データのバックアップ」(GET /api/backup) を取っていれば復元可能。
