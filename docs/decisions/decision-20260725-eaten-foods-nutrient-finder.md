# 「食べた食材から」栄養素を探す（過去1年・自分の記録から）

- 日付: 2026-07-25
- ステータス: 採用
- 関連: [[decision-20260724-dashboard-insights]]（寄与度）/ recommendation boundary（提案は事実提示のみ）
- 対応 issue: #28 の続き（食材の栄養寄与を「自分が食べた食材」から見たい）

## 背景

「栄養素から探す」「不足を補う候補」はカタログ全2,538品目から提案するため、
アセロラ・スモークレバーのような**現実に手に入りにくい食材**が上位に出る。
ユーザー要望: **提案は自分が実際に食べた食材の中から**分析したい（手に入るとは限らないため）。

## 決定（ユーザー確認済みの2点）

「栄養素から探す」に **「全食品 / 食べた食材から」トグル**を追加する。

- **対象範囲 = 過去1年（365日）に記録した食材**（ユーザー選択）。
- **並び順 = 100gあたりの含有量**（ユーザー選択・既存の効率指標と同じ）。
- 「食べた食材から」= 過去1年に記録した meals の distinct food_id に絞って、既存の
  `topFoodsByNutrient` で降順表示。ロジックは既存の read-only 参照ビューのまま。
- 事実提示のポリシー順守: notice を「過去1年に記録した食材のうち、含有量の多い順の
  事実表示で、摂取の推奨ではありません」に変更。断定・推奨はしない。

## この機能で満たせる目的（issueの3点との対応）
- **② 効率よく栄養素を摂れる食材** — 栄養素を選び「食べた食材から」で自分の食材を含有量順に。
- **③ 不足栄養素を摂るための食材** — 同上を不足栄養素で見る。
- **① 過剰摂取の原因食材** — 食塩は本 finder の対象外（more-is-better 限定・既存設計）。
  過剰の原因は別途「過剰行への寄与度内訳」で扱う（未実装・次の候補）。

## 実装
- domain `topFoodsByNutrient` に `allowedFoodIds?: ReadonlySet<string>` を追加（純粋・履歴知識なし）。
- handler `richFoods(nutrientCode, scope, deps)` … scope="history" で meals を読み、
  365日ウィンドウの distinct food_id を allowed set として渡す。`now` は注入可能（テスト用）。
- `GET /api/foods/rich?scope=history`（既存エンドポイントにパラメータ追加・契約は22オペのまま）。
- UI `NutrientFinder` にトグル＋空状態メッセージ（過去1年に該当食材がない場合）。

## 影響
- テスト 198 → 203（allowedFoodIds フィルタ2件・history scope 3件）。
- 契約は22オペのまま（パラメータ追加のみ）・`RichFoodsResponse.scope` を追加。
- 既存データ・凍結seed・栄養計算は不変（read-only）。
